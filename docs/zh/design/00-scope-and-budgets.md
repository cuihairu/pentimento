## P-001 V1 功能范围：R01–R19 逐项确认记录

下表为 R01–R19 与 D-01–D-19 的**已代决答案**（按推荐执行），并给出对用户含义与明确边界；即原 requirements 草案「待拍板」状态按本表落为「已代决」。

| 需求/决策 | 代决答案 | 对用户含义及明确边界 |
|---|---|---|
| R01 / D-01 | 纳入；支持可移动卷、本地文件系统上的库和跨卷重新定位 | 使用库内相对路径与稳定 ID；拔盘显示不可达，不自动新建空库；V1 不承诺网络共享承载运行中数据库。 |
| R02 / D-02 | 复制、递归、忽略、取消纳入；外部持续索引延后 | 管理的文件放进库里，原文件不动；用户修改原件不会同步到库内。 |
| R03 / D-03 | 名称、标签、格式、尺寸、评分可组合 | 基础属性筛选，条件同时生效，支持一键清除；不做自然语言/语义检索。评分范围须补进原验收（见 P-217）。 |
| R04 / D-04 | 五种位图格式验证；PSD 字节保留与降级必须，合成预览非硬门槛 | PSD 无法解码就写「暂无预览」；「原始字节预览」不是准确说法，应区分保存与显示。 |
| R05 / D-05 | 纳入标签/评分/备注/来源授权及库内文件夹 | 稳定 ID、相对路径先做；库内改名移动不割断历史，不追踪用户在库外任意搬移工作文件。 |
| R06 / D-06 | 手动、稳定变化记录、定时快照、暂停、排除、固定纳入 | 接受稳定判断为启发式，但增加读取前后状态复核与后台执行；文件监视器只作未来加速，不承诺捕获每次保存。 |
| R07 / D-07 | 元数据逐字段历史纳入 | 能看旧名称、标签、评分、备注、来源；暂不做多人合并和任意字段自动回退。 |
| R08 / D-08 | 整库一致快照、墓碑、时间点浏览纳入，作为 V1 门槛 | 时光机式体验的关键；快照保证已记录内容与清单的一致性，不宣称外部编辑器同时冻结。 |
| R09 / D-09 | 图像并排、同步缩放、滑动纳入 | 不做文本 diff、PSD 图层差异或三维模型差异；尺寸不同必须说明对齐方式。 |
| R10 / D-10 | 单素材和快照选中项恢复均纳入 | 恢复前列影响，先保存当前内容；不做一键抹平整个工作区。 |
| R11 / D-11 | 历史导出、恢复日志与重启收敛均为必需 | 中断后知道哪些完成、哪些需恢复；不把断电后的半恢复交给用户手工猜。 |
| R12 / D-12 | Git/LFS 整体延后 V1.x | 未来只读查看、提取，LFS 下载需同意；V1 不承诺 Git。 |
| R13 / D-13 | SVN 延后 V1.x，在有实际 SVN 使用者与样本后排期 | 未来只读并显示锁；不做提交、更新覆盖或锁管理。 |
| R14 / D-14 | 能力显示纳入；macOS 系统入口轻量纳入 | 经 macOS 验证后才显示入口，不读 Time Machine 备份内容，不宣传备份已成功。 |
| R15 / D-15 | 仅消费用户已挂载 SMB/NFS 目录，浏览并复制导入 | 不自行挂载/认证；持续索引随 R02 延后；备份可选已挂载目标。此为原验收调整。 |
| R16 / D-16 | WebDAV/SFTP 直连均延后 | 系统挂载先解决基本可达性，不能声称具备应用内直连。 |
| R17 / D-17 | mDNS、WS-Discovery 与合并过期整体延后 | V1 用系统目录选择器；不会自动寻找 NAS。 |
| R18 / D-18 | 本地任务/挂载失联状态纳入；协议地址表单与远端离线缓存延后 | 本地已导入副本照常浏览；不能把它称为远端离线缓存。TLS/SSH 校验随对应协议一起交付。 |
| R19 / D-19 | 一致性检查、空间预演、备份导出/演练纳入；实际清理不做 | 通过本地或挂载目标输出完整备份包；历史不自动删除，固定版本也不得列作清理对象。 |

**结论**：V1 主价值链为「本地复制导入 → 整理浏览 → 记录版本/整库快照 → 对比 → 预演 → 安全恢复/导出 → 可验证备份」。Git/SVN、WebDAV/SFTP、自动发现、外部目录持续索引延后，不承诺交付。

**明确不做/延后（V1）**：不把现有实验代码当 V1 完成证据；外部持续索引（P-204）、Git/LFS（P-401–P-405）、SVN（P-406–P-408）、WebDAV/SFTP 直连（P-502–P-505）、发现（P-506–P-508）、协议地址表单与远端离线缓存（P-509、P-514）、保留策略实际清理（P-602 仅预演）均不在 V1 交付范围，另行排期。

**待用户输入**：无（范围逐项确认已由代决授权；用户可推翻）。

## P-002 版本后端能力表（代决）

按决策：V1 仅自建后端可写；Git/LFS、SVN 延后但未来只读；Time Machine 仅系统入口。能力矩阵以「历史 / 树快照 / 恢复 / 锁 / 远端获取」分列填写 支持/不支持/未实现：

| 后端 | 历史 | 树快照 | 恢复 | 锁 | 远端获取 | 可写 | V1 边界 |
|---|---|---|---|---|---|---|---|
| 自建（SQLite+对象库） | 支持 | 支持（整库一致快照，P-311） | 支持（生成新版本） | 单进程写锁（QLockFile） | 不支持 | 是 | V1 核心 |
| Git（本地，未来） | 支持 | 支持（提交树） | 未实现（只读，仅提取/导出） | 不支持（不获取） | LFS 按需、须同意 | 否 | P-401–P-405，延后 |
| SVN（未来） | 支持 | 支持（revision 树） | 未实现（只读，仅提取/导出） | 支持（读锁信息） | 支持（按需） | 否 | P-406–P-408，延后 |
| Time Machine（macOS） | 未实现 | 未实现 | 未实现 | 不支持 | 不支持 | 否 | 仅系统入口提示（P-410–P-411），不解析备份格式 |

- **只读**仍可能发生下载/临时缓存（Git LFS 按需、SVN 按需），必须单独说明，避免误解为「完全不写任何磁盘」；V1 无直连后端，无此风险。
- 统一「支持历史」布尔值会掩盖树快照、锁和下载差别，故接口按能力独立查询（见 30-foundation.md#p-103）。

## P-003 NAS 接入范围调整记录（代决）

- **V1 范围（代决）**：仅消费用户已挂载 SMB/NFS 目录，**浏览并复制导入**；可向已挂载目标做备份导出（P-516）。不自行挂载/认证、不网络扫描、不把共享目录当多机共写素材库。
- **延后（V1.x）**：WebDAV/SFTP 直连（P-502–P-505）、mDNS/WS-Discovery 发现（P-506–P-508）、持续外部索引、远端离线缓存（P-514）。
- **原验收调整**：P-501 原验收「可索引已挂载共享」调整为「可浏览并复制导入已挂载共享；持续索引延后」。该调整列为**待批准**（见下）。
- **待用户输入**：
  - 用户能否自行挂载 SMB/NFS（决定「仅消费已挂载目录」是否满足实际场景）；
  - NAS 是导入来源还是备份目标（或两者），用于确定 P-516 目标与 P-604 测试矩阵；
  - P-501 新验收的批准（已代决为建议，用户可推翻）。

## P-004 测试样本与性能预算（代决）

### 样本矩阵（按表内算术修正）

`docs/zh/performance.md` 的「合计：2,090 个文件、约 30 GiB」为算术错误；按表内单文件体积重算为：

| 类别 | 格式 | 数量 | 单文件体积 | 小计（MiB） |
|---|---|---:|---:|---:|
| 基础位图 | PNG | 500 | 512 KiB | 250 |
| 基础位图 | JPEG | 500 | 1 MiB | 500 |
| 基础位图 | WebP | 500 | 512 KiB | 250 |
| 基础位图 | TGA | 500 | 2 MiB | 1,000 |
| 基础位图 | BMP | 500 | 2 MiB | 1,000 |
| 大图 | PNG | 20 | 64 MiB | 1,280 |
| PSD | PSD | 20 | 64 MiB | 1,280 |
| 源文件 | ZIP/其他 | 50 | 128 MiB | 6,400 |
| **合计** | | **2,590** | | **11,960** |

约 **11.68 GiB**（11,960 MiB ÷ 1024）。此修正应回写 `docs/zh/performance.md:18`（见 90-corrections.md 修正记录 C-01）。

### 两档样本预算（代决，D-20）

- **快速档：约 5 GiB** —— 降低每次回归成本，覆盖五种位图（PNG/JPEG/WebP/TGA/BMP）、PSD 降级与损坏样本，数量/尺寸按比例缩减。
- **完整档：约 11.68 GiB（表内修正值）** —— 保留大文件/格式覆盖（64 MiB 大图与 PSD、128 MiB 源文件）。
- **存储预算**还应包含工作副本、对象、备份等额外空间；不把「30 GiB」当采购/下载要求。
- 大于 256 MiB 的文件先测边界提示；**取消现有 256 MiB 上限另行为决策**（见待用户）。

### 测量口径与阈值（D-21/D-23）

用当前 Linux 环境做首个基线，同时记录 CPU、内存、磁盘、系统、Qt、插件与冷热缓存条件。原目标（先保留为实验目标，非通过承诺）：

| 指标 | 目标 | 测量口径（可验证） |
|---|---|---|
| 首次导入吞吐 | ≥ 100 MiB/s | 对象写入字节数/耗时，本地 NVMe，排除源目录扫描与网络；另报「备份当前状态」体积与耗时 |
| 缩略图生成 | ≥ 512 张/分钟 | 完整生成完成，不含队列等待 |
| 名称搜索 | P95 < 200 ms | 每条件至少 100 次，按 95% 请求响应；不含界面渲染 |
| 组合筛选 | P95 < 500 ms | 同上 |
| 时间轴打开 | < 500 ms | 单素材 100 版本 |
| 整库快照 | < 10 s | 2,000 资源，内容未变化 |
| 恢复 64 MiB | < 3 s | 含哈希校验 |

- **另测**从操作到显示结果的用户等待时间与界面可响应性，给出预算供批准（决策 P-609 前）。
- 网络速度不混入本地 NVMe 基准；不只凭数据库查询快就宣称流畅；未获测量证据前不自动收紧/放宽。
