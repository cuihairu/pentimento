## P-601 对象与索引一致性检查（V1 可靠性门槛）

先报告后处理。**只读扫描报告**定义，覆盖：对象缺失（清单有、对象无）、损坏（哈希不符）、孤立（对象无引用）、失效引用（资源引用缺失对象）、磁盘错误（读取 I/O 失败）。后台进度；**不自动修复、不删孤立对象、不改写损坏历史**（先报告，处理另行决策）。

**实现（2026-11-01）**
- 设计：`Library::checkConsistency(progress)` 只读报告——枚举全部修订引用（含已删素材的历史，时间线仍持有对象）得 哈希→尺寸/引用数；逐引用哈希核对对象文件存在（缺失）、尺寸相符且流式内容哈希一致（损坏）、打开/读取失败（I/O 错误）；枚举 `objects/` 中无任何引用者（孤立）；`progress` 报告 百分比+当前哈希 供后台 UI。异常只在库根本不可读时抛出；单个对象问题一律进报告不抛。
- 范围：**不自动修复、不删孤立、不改写损坏历史**（报告是后续决策输入，与 P-602/P-603 配合：缺失/损坏可从备份包恢复，孤立待未来清理决策）。
- 接线：「一致性检查…」工具栏动作——后台写者队列执行（读全部对象，大库不阻塞界面）→ 结果对话框：修订引用数/对象文件数/校验通过数 + 缺失/损坏/孤立/I/O 计数与截断明细（各 20 条）。
- 测试：`consistencyCheckReportsCleanLibrary`（干净库 0 问题、进度回调被调用）、`consistencyCheckReportsMissingCorruptOrphan`（删对象→缺失、改字节→损坏、无引用文件→孤立；报告只读不改动存储）。
- 验证：ctest 2/2 绿；离线烟雾运行无崩溃；lupdate/lrelease 351/351 双语言完成。

## P-602 空间与保留策略预演（不实际清理）

- 区分：逻辑大小（清单合计）、物理占用（磁盘实际）、共享对象（被多版本引用，去重后）、固定版本（受保护）、理论可回收量。
- 简单相加文件大小会高估可回收空间（共享对象重复计数）→ 用共享对象引用计数估算。
- 空间不足提示：预演列出缺口与占用去向，不实际删除。
- 无清理也意味着磁盘持续增长（明确说明）。

**实现（2026-11-01）**
- 设计：`Library::spacePreview()` 只读预演——枚举全部修订得 逻辑大小（清单合计，共享内容重复计数，正是要怀疑的数）/固定版本（P-307 钉住：条数+字节）；枚举 `objects/` 得 物理占用（对象文件实际）/共享对象（被 >1 修订引用：个数+去重节省字节）/理论可回收（仅无任何引用的孤立对象字节——无清理政策前是唯一真实浪费）。**不实际删除、不自动清理**；磁盘随版本持续增长（明确提示）。
- 接线：「空间预演…」工具栏动作——后台写者队列执行 → 对话框：素材/修订数、逻辑 vs 物理、共享对象+去重节省、固定版本+字节、理论可回收+孤立数，并说明当前不做清理。
- 测试：`spacePreviewDistinguishesLogicalPhysicalSharedOrphan`（同内容两修订共享一对象：逻辑重复计数/物理一次；钉住一修订→固定字节；孤立文件→可回收=其字节）。
- 验证：ctest 2/2 绿；离线烟雾运行无崩溃；lupdate/lrelease 356/356 双语言完成。

## P-603 可恢复备份校验流程

完整恢复演练为备份成功的证据，在**独立空目录**操作（不覆盖原库）。核对报告逐项：空目录恢复、内容哈希、资源 ID、版本数、路径、元数据。可选择代表性样本先演练。**不只检查「备份文件存在」**；校验压缩包/文件数不能发现索引与对象对应错误。

**实现（2026-11-02）**
- 设计：`Library::restoreBackupPackage(packageDir)` 恢复演练——目标必须是**新建空库**（已有素材即拒绝：演练绝不覆盖原库）；先 `verifyBackupPackage`（标记+清单+对象逐哈希校验）通过才落物；逐清单条目把对象复制进目标库 objects/（复制后再次校验尺寸+内容哈希），以**清单记录的资源 ID/名称/文件夹**重建资产与工作副本（复制后再哈希校验），写入一条版本（新自增 ID，哈希/尺寸保真）——单事务，失败整体回滚。
- 核对报告逐项（演练证据，非「备份文件存在」）：空目录恢复、内容哈希（对象+工作副本）、资源 ID、版本数（每条目恰一版且哈希相符）、路径（folder/name 保真）。
- 接线：「恢复演练…」工具栏动作——选备份包目录 → 选独立空目录 → 确认 → 后台队列在独立库执行恢复并重读恢复目录逐条核对 → 报告 全部通过 N / 部分核对失败 x/y(明细)；失败明确提示「备份不可视为可用」。
- 测试：`backupPackageRestoreDrillRebuildsIndependentLibrary`（恢复后：ID/路径/版本数/哈希/工作副本逐项比对清单）、`backupPackageRestoreRefusesExistingLibrary`（目标库非空即拒绝）。
- 验证：ctest 2/2 绿；离线烟雾运行无崩溃；lupdate/lrelease 371/371 双语言完成。

## P-605 故障与恢复场景（V1 发布前硬门槛）

用**隔离测试库**（非真实素材库）覆盖：对象写入、索引提交、备份、恢复四阶段故障；各阶段中断留重开后的证据（见 50-versioning#P-320 阶段表）。磁盘满、中断、损坏、冲突各有可解释结果。**不在真实素材库注入故障**；不把未通过项写成已知限制后直接放行核心恢复。

**实现（2026-11-02）**
- 故障矩阵（隔离测试库，非真实素材库；各阶段中断留重开证据）：
  - **对象写入**：`storeObjectFromFile` 哈希先校验再改名——半写入不可能被引用。重开证据：残留 `objects/.tmp` + 坏对象 → `checkConsistency` 报 **损坏**（绝不静默信任）；工作副本/目录完好，库仍可导入。测试 `faultInterruptedObjectWriteIsReportedNotTrusted`。
  - **索引提交**：对象已存、索引未提交（断电窗口）→ 完整但无引用的对象。重开证据：报 **孤立**（索引无悬空引用），修订/目录完好，仍可记录版本。测试 `faultInterruptedIndexCommitLeavesOrphan`。
  - **备份**：导出中断 → 无 `COMPLETE` 标记的半包 → `verifyBackupPackage` 拒绝（不标成功），见 P-516 `backupPackageVerifyRejectsHalfPackage`。
  - **恢复**：P-320 四阶段（保护/写日志/替换文件/提交索引），断电窗口由 `convergeRestoreLog` 向前/向后/冲突收敛，见 `interruptedRestoreConvergesForwardOnReopen`/`BackwardOnReopen`。
- 磁盘满/中断/损坏/冲突各有可解释结果（损坏→报告、孤立→报告、半包→拒绝、恢复中断→收敛）；**不在真实素材库注入故障**；不把未通过项写成已知限制放行。
- 验证：ctest 2/2 绿；离线烟雾运行无崩溃。
